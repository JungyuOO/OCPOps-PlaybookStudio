PBS Lightspeed RAG 챗봇 Fallback 및 Timeout 간이 정리

작성일: 2026-06-08 · 대상: feat/kugnus-dev2.3 · 범위: Lightspeed RAG 챗봇 경로 한정

현재 동작 구조

  • 사용자 질문이 OpenShift 운영 질문이면 PBS는 먼저 OpenShift Lightspeed API를 호출한다.
  • Lightspeed가 정상 답변을 반환하면 PBS는 답변 원문을 재작성하지 않고 lightspeed_with_pbs_rag로 반환한다.
  • 이때 관련 링크와 citation은 /external/lightspeed/<artifact_id> viewer로 연결된다.
  • PBS 내부 Gold RAG는 Lightspeed가 비활성, 오류, 빈 응답, timeout인 경우 fallback 근거로 사용된다.

이번 수정 사항

  • 기존 2.3에는 enabled_source_scopes가 있으면 Lightspeed를 건너뛰는 조건이 있었다.
  • 웹 UI는 기본적으로 official_docs, customer_docs, user_upload scope를 보내므로, 일반 운영 질문도 Gold RAG로 빠지는 문제가 생겼다.
  • 이번 수정으로 source scope는 PBS 내부 fallback 검색 범위에만 영향을 주고, OpenShift 운영 질문의 Lightspeed 우선 호출은 막지 않도록 했다.

Timeout 조정

  • Lightspeed timeout 기본값을 25초에서 35초로 늘렸다.
  • Ingress NodePort 질문처럼 Lightspeed 내부 RAG 문서가 여러 개 붙고 답변 재구성이 필요한 경우, 성공 응답도 14~23초까지 걸렸다.
  • 기존 25초는 이런 질문에서 timeout 경계에 가까워, 조금만 지연되어도 Gold fallback으로 내려가는 문제가 있었다.
  • 35초로 늘려도 빠른 질문이 항상 35초를 기다리는 것은 아니다. Lightspeed가 8초에 답하면 8초에 바로 반환된다.
  • 영향이 있는 경우는 25초를 넘지만 35초 안에는 답할 수 있는 느린 Lightspeed 질문이다.
결론: PBS는 OpenShift 운영 질문에서 Lightspeed를 우선 호출하고, Lightspeed가 실패하거나 timeout인 경우에만 Gold RAG로 fallback한다. 이번 수정은 source scope가 Lightspeed 우선순위를 깨지 않게 분리하고, 느린 Lightspeed RAG 답변에 35초까지 여유를 주는 것이다.
