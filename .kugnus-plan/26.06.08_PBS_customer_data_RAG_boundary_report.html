1. 현재 판단

결론: 고객 PPT는 PBS RAG 경로에 연결되었지만, 원본 PPT가 바로 고품질 운영 RAG 코퍼스가 되는 상태는 아니다. 따라서 고객데이터를 일반 운영 질문에 자동으로 넓게 섞는 방식은 위험하며, 고객자료를 명시한 질문에만 제한적으로 사용해야 한다.
  • 고객데이터 연결성은 확인됐다. 챗봇 citation, source-meta, viewer가 Customer Data로 이어진다.
  • 그러나 고객 PPT의 parsed_documents.markdown은 모든 study_docs 문서에서 0자였다.
  • RAG 검색에 쓰이는 document_chunks는 존재하지만, 슬라이드 이미지 설명/요약/중복 텍스트가 섞여 있어 품질 편차가 크다.
  • OpenShift Lightspeed는 고객 PPT를 직접 알지 못하므로, 고객자료 명시 질문에서 Lightspeed 원문을 그대로 반환하면 고객데이터와 충돌하는 답변이 나올 수 있다.

2. 확인된 현상

사용자 테스트 질문

성능 테스트 결과 기준으로 현재 OCP 운영 준비 리스크를 정리해줘

관찰된 답변 문제

  • 답변은 LIGHTSPEED badge로 반환됐다.
  • Lightspeed는 “제공된 문서에는 성능 테스트 결과 데이터가 포함되어 있지 않다”고 답했다.
  • 이후 실제 질문과 무관한 Compliance Operator, oc-compliance 중심 답변으로 흘렀다.
이 현상은 고객데이터 검색 연결이 완전히 없어서라기보다, 고객자료 명시 질문에서 답변 생성 주체가 Lightspeed passthrough로 유지된 것이 핵심 문제다. Lightspeed는 고객 PPT를 보지 못하므로 “성능 테스트 결과 없음”이라고 말할 수 있다.

문서 상태 운영 답변 활용 가능성

4. 이번 작업 내용

구현된 연결성

  • Wiki Library에 고객 데이터 surface를 추가해 study_docs PPT 목록을 볼 수 있게 했다.
  • 고객 PPT viewer/source-meta가 Customer Data, study_docs, customer_data로 표시되게 정리했다.
  • 챗봇 citation 모델에 source_scope를 보존해 고객자료 출처가 프론트까지 유지되게 했다.
  • 완료보고서, 고객 데이터, PPT, 설계서, 성능 테스트 등의 신호를 고객자료 검색 신호로 감지하도록 했다.
  • 고객자료가 명시된 질문에서 원문 검색어를 보존해, 재작성된 공식문서 검색어 때문에 고객자료가 밀리지 않도록 했다.

검증된 연결성

  • /api/chat에서 고객자료가 잡히는 경우 Lightspeed + Customer 및 Customer Data citation이 반환됨을 확인했다.
  • /api/source-meta가 boundary_badge=Customer Data, runtime_truth_label=Customer Data Document로 응답함을 확인했다.
  • /api/viewer-document가 고객 PPT viewer HTML과 완료보고 텍스트를 반환함을 확인했다.

5. 제품 경계 결정

질문 유형 권장 라우팅 이유
일반 OCP 운영 질문 Lightspeed 우선 공식 OpenShift 운영 지식은 Lightspeed/Gold가 더 안정적이다. 고객 PPT를 억지로 섞으면 오답 리스크가 커진다.
고객 데이터 기준, 완료보고서 기준, 성능 테스트 결과 기준 등 Customer-first PBS RAG 질문자가 고객자료를 기준으로 요구했으므로 Lightspeed passthrough가 아니라 PBS가 고객자료를 읽고 답해야 한다.
고객자료 검색 결과가 빈약한 질문 근거 부족/범위 제한 고객 PPT chunk 품질이 낮으면 억지 합성을 피하고 확인 가능한 범위를 명시해야 한다.
향후 고도화 방향은 “고객자료 자동 매칭 확대”가 아니라 “고객자료 명시 질문의 customer-first RAG 경로 분리”다. 이 경로에서는 Lightspeed 답변을 그대로 반환하지 않고, 고객자료 citation을 중심으로 PBS가 답변을 생성해야 한다.

7. 다음 행동 제안

  1. 현재 수준에서 고객데이터 자동 매칭 확장은 중단한다.
  2. 고객자료 명시 질문에 한해 customer-first route를 별도로 설계한다.
  3. PPT 원본을 바로 RAG 본문으로 쓰지 말고, 문서별 “운영 지식 카드”를 생성한다.
  4. 운영 지식 카드는 환경 사실, 운영 절차, 테스트 근거, 리스크/제약으로 분해한다.
  5. 문서 품질 게이트를 두어 markdown=0, tiny chunk 비율, image-only 비율을 표시하고 낮은 품질 문서는 답변 합성에서 제한한다.
